# Contributing to EIOS SDK

Thank you for your interest in contributing to emotional safety infrastructure!

## How to Contribute

### 1. Code Contributions

- Fork the repository
- Create a feature branch (`git checkout -b feature/amazing-feature`)
- Write tests for your changes
- Ensure all tests pass (`pytest tests/`)
- Submit a pull request

### 2. Cultural Profiles

We need more cultural profiles! To contribute:

1. Research emotional expression norms in your culture
2. Cite peer-reviewed sources
3. Consult with cultural insiders
4. Submit profile following existing format
5. Include calibration data

### 3. Documentation

- Fix typos and unclear explanations
- Add examples
- Translate documentation
- Write tutorials

### 4. Bug Reports

Include:
- EIOS version
- Python version
- Minimal reproduction code
- Expected vs. actual behavior
- E_STATE and metrics at time of bug

### 5. Feature Requests

- Describe the use case
- Explain emotional safety benefit
- Propose implementation approach
- Consider cultural implications

## Code Standards

- Follow PEP 8
- Type hints required
- Docstrings for all public functions
- Tests for all new features
- No reduction of safety guarantees

## Cultural Sensitivity

When contributing:

- Never impose universal emotional norms
- Respect cultural sovereignty
- Cite research from cultural insiders
- Test across cultural contexts
- Consider colonization risks
